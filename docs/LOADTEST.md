## What changed to get here (P7.3)
- `GET /api/public/resolution-rate` grouped rows quadratically: **290 ms → 0.9 ms** at 20k complaints. It now has a short revision-aware cache (exact when idle, ≤ 5 s old under load).
- `GET /api/dept/:id/complaints` returned the whole department (13k objects per request). It is now newest-first with 500 per page by default and a `before` cursor (D-046).
- The first run hit the per-IP write limiter: all traffic came from one address. Real clients have their own addresses, so the test now sends a distinct `X-Forwarded-For` per simulated person through the trusted proxy.

## Limits (honest)
- **Machine:** one 4-vCPU machine, load generator in the same process. Run `loadtest/k6.js` from a separate machine against staging before go-live.
- **Scale-out:** one API instance holds the working set in memory (D-029). Going beyond one instance per state needs read-through queries on the Postgres driver.
- **Not measured:** WebSocket fan-out to the citizen app, and media uploads, are not part of this run.
